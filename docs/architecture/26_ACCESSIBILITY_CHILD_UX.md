# 26 — Accessibility, Child UX and Transparency

## 1. Child experience principles

- explain limits without shaming language;
- show exact remaining time where reliable;
- distinguish “parent rule” from “technical problem”;
- provide a respectful request-more-time path;
- never hide emergency access;
- explain monitoring in age-appropriate language.

## 2. Required child screens

1. Today / Remaining Time
2. Break Screen
3. Eye Protection
4. Prayer Times
5. Request More Time
6. Protection Status
7. What Parents Can See
8. Privacy and Data
9. Emergency

## 3. Accessibility

- semantic labels for controls;
- screen-reader support;
- large text/dynamic type;
- sufficient contrast;
- reduced-motion support;
- no critical information communicated only by color/sound;
- Arabic screen-reader labels tested.

## 4. Break/Dhikr UX

Dhikr/reflection is optional family content and must not prevent emergency access. The child can see both Arabic and optional English meaning based on language settings.

## 5. Error/degraded states

Example:
> “Web protection is temporarily unavailable. Your parent has been notified.”

Do not falsely show “Protected” when VPN/authorization is inactive.

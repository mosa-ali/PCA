## Completion framework

Every phase is reported on three independent tiers (doc 00 Section 8A). The tiers are never inferred from one another.

- **`SOURCE_COMPLETE`** — code exists implementing the phase's scope. `YES`, `PARTIAL` (with the missing scope named), or `NO`.
- **`VALIDATED_COMPLETE`** — tested against acceptance criteria with recorded, reproducible evidence. Values used below: `PARTIAL` (automated unit/integration/DB evidence exists and was executed on 2026-09-08, but the phase's real-device, real-provider or real-human acceptance evidence does not), `NO` (no executed evidence), or `YES` only where every acceptance criterion is automated and executed. **No phase reaches `YES` today**, because doc 28's device/E2E, privacy-absence-on-device and UAT layers have never been executed (`docs/release_readiness/uat_execution_log.json` is `NOT_EXECUTED`, 0 of 54 cases).
- **`PRODUCTION_READY`** — every applicable doc 31/`external_gate_matrix.json` gate closed. All 39 registered gates are open, so **no phase is `PRODUCTION_READY`**.

Executed evidence behind the `PARTIAL` validations on 2026-09-08 (local, disposable environments; nothing deployed): backend non-DB suite 2,330 → 2,336 tests after this pass, 0 failures; backend MySQL 8.4 suite 532 tests, 528 pass, 4 privilege-gated skips; parent-web Vitest 996 tests, 0 failures; platform-admin-web Vitest 153, 0 failures; Android JVM 1,347 tests, 0 failures, 1 skipped; parent-web Playwright 65/68 (3 click-timeouts under host contention, re-run individually — see the assessment); platform-admin-web Playwright 15/15; four contract catalogues validated (the runtime-sync validator now reconciles routes and error codes against source); release-gate tooling 0 failures across all six targets.

## Programme control

- one main orchestrator;
- exact file/module ownership;
- no uncontrolled parallel writes to shared files;
- implementation agents must test their owned slice;
- independent red-team verification before phase acceptance;
- no "100% complete" report while any acceptance criterion is partial — and, per the three-tier framework above, no report may claim `VALIDATED_COMPLETE` or `PRODUCTION_READY` on the strength of `SOURCE_COMPLETE` alone;
- **this document is regenerated from executed evidence at every assessment pass, never edited to match a wish.** If it disagrees with `docs/supervision/PCA_FINAL_GAP_ASSESSMENT_2026-09-08.md` or a later assessment, the later dated assessment wins and this file is stale.
